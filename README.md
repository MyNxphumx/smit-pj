# ต้นแบบสำนักสาธารณสุขและสิ่งแวดล้อม เทศบาลนครขอนแก่น

เว็บภาษาไทยทั้งฝั่งเจ้าหน้าที่ 7 เมนูและฝั่งประชาชน ใช้ HTML/CSS/JavaScript โดยไม่ต้องติดตั้งไลบรารีเพื่อเปิดใช้งาน ข้อมูลและภาพเก็บใน IndexedDB ของเบราว์เซอร์ ไม่ส่งข้อมูลออกไปภายนอก

## เปิดใช้งาน
ต้องมี Node.js 22 ขึ้นไป เปิด Terminal ในโฟลเดอร์นี้ แล้วรัน:

```powershell
npm start
```

เปิด http://127.0.0.1:5173 ใน Chrome หรือ Edge หากมีเซิร์ฟเวอร์เปิดอยู่แล้ว สามารถเข้า URL นี้ได้ทันที ใช้ origin นี้สม่ำเสมอ เพราะ localhost และ 127.0.0.1 มีพื้นที่จัดเก็บคนละส่วน

ตรวจสอบไฟล์ส่งมอบ:
```powershell
npm run build
```
ไฟล์พร้อมใช้งานอยู่ใน dist/ ไม่ต้องมี backend

## วิธีสาธิต
- ใช้ปุ่ม “ฝั่งประชาชน / ฝั่งเจ้าหน้าที่” ด้านบน ไม่ต้อง Login
- ฝั่งประชาชนกรอกคำร้อง แนบ JPG/PNG สูงสุด 3 ภาพ ภาพละ 2 MB เก็บเลขคำร้องที่แสดงหลังส่ง
- เปลี่ยนเป็นฝั่งเจ้าหน้าที่ เปิดข้อร้องเรียน กดเลขคำร้องเพื่อมอบหมายและบันทึกความคืบหน้า แยกข้อความสำหรับประชาชนและบันทึกภายใน
- ก่อนปิดเรื่องต้องมีผลแก้ไขและยืนยัน จากนั้นใช้เลขคำร้องเดิมเพื่อติดตามในฝั่งประชาชน
- เลขคำร้องตัวอย่าง: KK-2569-0003
- ข้อมูลประชาชน → ค้นหา → รายละเอียด → บันทึกเยี่ยมบ้าน จะเลือกบุคคลนั้นล่วงหน้า ระบุวันติดตามเพื่อสร้างนัดเชื่อมโยง
- สถานประกอบการ → รายละเอียด → บันทึกตรวจ / ตรวจติดตาม งานที่ต้องปรับปรุงจะปรากฏในหน้าติดตามงาน
- โครงการ → รายละเอียด มีแท็บข้อมูล หน่วยงานร่วม ประสานงาน และผลดำเนินงาน ต้องบันทึกผลก่อนปิดโครงการ
- “อ่านแล้ว” เป็นสถานะการอ่านเท่านั้น ต้องดำเนินงานจากต้นทางเพื่อให้งานค้างเปลี่ยน
- รีเซ็ตจากปุ่มด้านล่าง Sidebar หรือท้ายหน้าประชาชน แล้วยืนยัน ข้อมูลที่เพิ่มและภาพจะถูกลบ กลับเป็นข้อมูลเริ่มต้น
- ข้อมูลเริ่มต้น: ประชาชน 12 คน คำร้อง 8 เรื่อง สถานประกอบการ 6 แห่ง โครงการ 4 โครงการ และข้อมูลเชื่อมโยง ใช้วันที่ปัจจุบันเขตเวลาไทยเป็นฐาน

## ข้อจำกัด
ใช้ข้อมูลสมมติเท่านั้น การสลับบทบาทและรหัสติดตามไม่ใช่ระบบรักษาความปลอดภัยจริง ข้อมูลอยู่เฉพาะเบราว์เซอร์และ origin เดิม ไม่รองรับข้ามอุปกรณ์ ไม่มี Login ฐานข้อมูลกลาง LINE ระบบโรงพยาบาล การส่งข้อความจริง ใบอนุญาตออนไลน์ หรือ AI พื้นที่จัดเก็บขึ้นกับเบราว์เซอร์ การล้างข้อมูลเว็บไซต์จะลบข้อมูลต้นแบบ ข้อมูลส่วนตัวทั้งหมดอยู่ใน IndexedDB แม้หน้าติดตามจะไม่แสดงบันทึกภายในก็ตาม

Preview ฝังในแชตและการตรวจหน้าจอจริงไม่สามารถทำได้ในสภาพแวดล้อมนี้ เพราะไม่มีเบราว์เซอร์เชื่อมต่อ ใช้ URL localhost เปิดบนเครื่องผู้ใช้ รองรับมือถือด้วย responsive CSS แต่ยังไม่ได้ตรวจภาพหน้าจอในเบราว์เซอร์จริง ส่วน WebMCP เป็นตัวเลือกเมื่อเบราว์เซอร์รองรับ ยังไม่ผ่านการตรวจในบริบท WebMCP จริง

## Node และโฮสต์
- npm start จะ Build อัตโนมัติ แล้วเปิดผ่าน Node ที่ http://127.0.0.1:5173
- npm run dev เปิดจากไฟล์ต้นฉบับสำหรับแก้ไข
- เปลี่ยนพอร์ตใน PowerShell: $env:PORT="5180" แล้ว npm start
- หากใช้โฮสต์ Node กำหนด HOST=0.0.0.0 และ PORT ตามผู้ให้บริการ
- เซิร์ฟเวอร์ให้เข้าถึงเฉพาะไฟล์เว็บ ไม่เปิด source, package.json หรือข้อมูลตั้งค่าภายใน
- เว็บไซต์ออนไลน์ใช้ไฟล์ dist ผ่าน Sites ไม่ต้องมี Node ทำงานบนโฮสต์ ข้อมูลยังอยู่ในเบราว์เซอร์แต่ละเครื่อง ไม่ได้กลายเป็นฐานข้อมูลกลาง
- ตัวเลือกโฮสต์ฟรีอื่น: Cloudflare Pages (อัปโหลด dist) https://developers.cloudflare.com/pages/functions/pricing/

## ติดตามคำร้องด้วยช่องเดียว
กรอกเลขคำร้องหรือเบอร์โทรศัพท์ที่ระบุไว้ในช่องทางติดต่อ ระบบแสดงคำร้องที่ตรงกัน รองรับรูปแบบ 0800000000, 080-000-0000 และ +66 80 000 0000 หากแจ้งด้วยอีเมลให้ใช้เลขคำร้อง ไม่ใช้เลขบัตรประชาชน

## ประเมินความพึงพอใจ
หลังคำร้องมีสถานะแก้ไขแล้ว ประชาชนสามารถเลือก 1–5 ดาวและกรอกความคิดเห็นได้หนึ่งครั้งต่อคำร้อง คะแนนจะปรากฏในรายละเอียดและภาพรวมเจ้าหน้าที่ เก็บใน IndexedDB เดียวกับคำร้อง การคืนค่าข้อมูลจะลบผลประเมินด้วย

## ทะเบียนสถานประกอบการ
เมนูทะเบียนสถานประกอบการแสดงเจ้าของ วันที่เปิด วันหมดอายุใบอนุญาต และผู้รับรอง โดยเรียงวันหมดอายุจากเร็วไปช้า กรองหมดอายุ วันนี้ ใกล้หมดอายุภายใน 30 วัน และยังไม่หมดอายุได้ เปิดรายละเอียดเพื่อแก้ไขข้อมูลใบอนุญาต ข้อมูลเริ่มต้นของ 6 ร้านเป็นข้อมูลสำหรับสาธิต ไม่ได้ตรวจสอบกับหน่วยงานออกใบอนุญาต

## โครงสร้างเมนูที่รวมแล้ว
เหลือ 6 เมนู: ภาพรวม, ผู้รับบริการและการดูแล (ทะเบียน / นัดเยี่ยมบ้าน), เรื่องร้องเรียน, สถานประกอบการและใบอนุญาต (ทะเบียน / ตรวจสุขาภิบาล), โครงการและเครือข่าย, แจ้งเตือนและติดตามงาน รายละเอียดร้านรวมข้อมูลใบอนุญาตและประวัติการตรวจในหน้าต่างเดียวกัน Dashboard และงานติดตามคำนวณจากข้อมูลต้นทาง ไม่จัดเก็บสำเนาแยก คะแนนความพึงพอใจเชื่อมกับคำร้องเดิม

ทะเบียนผู้รับบริการถูกนำออกจากเมนู การเยี่ยมบ้านยังเลือกบุคคลจากข้อมูลเดิมได้ ข้อมูลและประวัติไม่ถูกลบ

## กระบวนงานเจ้าหน้าที่ที่เพิ่ม
ดู WORKFLOWS.md สำหรับแหล่งข้อมูล ขั้นตอน เงื่อนไข และวิธีทดสอบ เพิ่มบุคคลได้จากนัดเยี่ยมบ้าน เพิ่มร้านใหม่และบันทึกต่ออายุได้ แก้ข้อมูลคำร้องพร้อมเหตุผล บันทึกผลติดตามโครงการก่อนปิด และรวมใบอนุญาตในงานติดตาม ทุกการเปลี่ยนแปลงมีประวัติ

## Deploy บน Render
ใช้ New > Blueprint เชื่อม repository นี้ ระบบอ่าน render.yaml และเผยแพร่ไฟล์ dist เป็น Static Site ชื่อ khonkaen-health ใช้ Node เพื่อ Build ไม่ต้องมี Web Service ทำงานตลอดเวลา URL ที่ได้ลงท้าย .onrender.com ตามชื่อที่ว่าง ข้อมูลยังเก็บในเบราว์เซอร์แต่ละเครื่อง
